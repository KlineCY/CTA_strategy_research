# 测试与复现

## 可执行检查

源代码提供输入、时间边界、模型选择、仓位求解和账户核算的自动测试。测试中涉及真实市场日历、缺价窗口和历史标签的部分，依赖运行者在`data/raw/`提供与[输入说明](../data/INPUTS.md)一致的41个文件。没有这些输入时，依赖市场数据的测试会跳过；独立于行情的测试仍可运行。项目命令依次覆盖输入核验、样本月预测与账户快速检查，以及全量研究：

```powershell
python -m pip install -e ".[dev]"
python -m cta_project.cli validate-data
python -m pytest -q
python -m cta_project.cli smoke
python -m cta_project.cli run --workers 4
```

快速检查运行2024年6月的Ridge逐月模型，核对预测与协方差的有限值、求解约束、现金加持仓市值恒等式、费用入账及执行比例为1时的账户一致性。全量运行遍历七类模型和每模型14×14组组合参数，按输入与代码指纹缓存预测月份和参数批次。

## 已完成研究的汇总

结果CSV记录项目全量回测的阶段汇总。原始输入不随仓库提供，因此仅凭仓库中的文件无法重新计算表中数值。Validation选择的预测模型为Ridge，组合参数`λ=0.005`、`γ=0.0025`，风险控制方案为不额外缩仓的基础组合。滚动样本外残差协方差对照只作诊断。

数值见[三阶段最终选定账户表现](../results/三阶段最终选定账户表现.csv)。Training预测逐月使用既往数据，但组合参数取自Validation，Training账户曲线为事后参数诊断。历史账户使用完整五日窗口排除缺价资产，因而与实时可执行交易有差别；费用未覆盖分红、融资、借券和滑点。

## 结果核对

完整运行后，`results/run_manifest.json`记录41个输入文件及源码、配置、环境的SHA256指纹。Validation波动率特征选择只比较共同样本；模型误差只计算已成熟标签；组合网格按同一目标函数和费用口径评价。每批目标权重满足单资产−10％至＋20％、净敞口90％至100％、总敞口280％至300％；五批叠加后的逐日实际敞口另行统计。账户净值由现金与持仓市值之和核对，费用在成交日进入现金。等权买入并持有基准计入买入及期末卖出费用，缺价日只展示完整报价的净值。

结果目录保存新的逐月预测、组合网格、图像和运行指纹。若输入、代码、设置或依赖版本变化，指纹检查会阻止把既有缓存与新运行混用。仓库中的汇总CSV对应既定输入与设置。运行指纹约束缓存复用，但不会自动保留被同名文件覆盖的历史汇总；不同数据版本的结果分别保存，才能准确比较。
